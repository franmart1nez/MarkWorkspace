# World in Dreams — working rules for agents

A personal browser game: a painted, top-down fantasy world that simulates
itself and is watched, not played. Version 0.3.5 is one walled city and five
villages with about 1,800 individuals simulated minute by minute. It runs on
this computer only and is not published.

## Direction

- **Only the current game and the roadmap matter.** The first goal of the
  project (a continent of 33 species with realms and wars, a protagonist, a
  text RPG, AI agents, the Spanish GDD) was abandoned on 2026-11-18. Do not
  plan, document or build toward it, and do not restore it from Git history.
- The roadmap restarts from the ground up: a living land with animals and no
  people (M1–M3), then today's kingdom moved onto it (M4–M6), then society
  (M7–M8), attributes, combat and magic (M9–M10), richer cities and monster
  peoples (M11–M12). Work is chosen by task number, for example **1.7.6**.
- The owner likes the current art; keep the art bible's rules.

## Engine rules (do not break)

- **Determinism.** Every random draw goes through `src/engine/rng.js` with its
  state in `S.rng`; never `Math.random()`, `Date.now()` or iteration order of
  unsorted object keys in engine decisions. The same seed and calendar must
  give the same history; the level of detail must never depend on the camera.
- **Only `step(S)` changes the world.** The viewer, scripts and future tools
  read the state and the layout; they never write to them.
- **Static data is rebuilt, not saved.** Layout and interiors come from the
  seed; the save holds only dynamic state.
- **Declare every field at creation** (`makePerson`, `settle`, businesses,
  herds). Adding or deleting properties later halves the tick's speed in V8.
- **Changing the shape of `S`** means a new save version, updated checks in
  `deserialize` (`index.js`) and `validateWorld` (`src/ui/viewer-tools.js`),
  and a test that refuses — or, once M5.4.2 exists, upgrades — older saves.
- **No dependencies and no build step.** Plain ES modules for Node 22+ and
  modern browsers.
- **Stored text is English** (code, docs, in-game text). Talk to the owner in
  their language.

## Building a new system

Target contract (roadmap 1.1.3; existing code does not follow it yet):

| Part | Requirement |
| --- | --- |
| Module | One file or folder per system under `src/engine/` |
| State | The system owns a named slice of `S`, declared at world creation |
| Clock | States how often it runs (minute, hour, day, week, season, year) |
| Reads / changes | Lists the other slices it reads and the actions it takes on them |
| Events | Publishes events through the chronicle (`log`) and, later, the event bus (M5.5.2) |
| Data | Content in tables (species, animals, trades, spells), not in branches |
| Tests | Determinism, save round-trip, and its own balance check over a long run |
| Docs | A section in `docs/systems.md` and a plain summary in the card's `SYSTEMS.md` |

Keep today's city region working until M4 replaces it (roadmap rule 7).

## Finishing a task

1. `npm test` passes. Add tests for new behaviour.
2. Check speed with a headless run (`npm run sim -- dreams 48 3`; the last
   line reports the time) and compare with the 2026-11-18 figure (one year
   ≈ 5 s).
3. For visible changes, run the game and capture it; do not claim visual
   results that were not observed.
4. Tick the task in `ROADMAP.md` (`- [x]`) only when it works in the game, then
   run `npm run roadmap` to refresh the progress tables.
5. Update `docs/systems.md` / `docs/architecture.md`, and the card's
   `SYSTEMS.md` or `OVERVIEW.md` "At a glance" numbers when they change.
6. At the end of a milestone, run the quality gate (roadmap rule 6) and record
   the result in a dated note in the card, linked from the Overview.
7. Update `updated` for `world-in-dreams` in `workspace/workspace.json`.

## Legacy

`archive/v1-continent/` is the abandoned v0.1 (continent, 33 species). It is
not part of the game: do not run, extend or document it. Its terrain code
(`archive/v1-continent/src/engine/map.js`, biomes from noise) may be read as an
idea source for M1; anything reused must be rewritten to the current rules.
